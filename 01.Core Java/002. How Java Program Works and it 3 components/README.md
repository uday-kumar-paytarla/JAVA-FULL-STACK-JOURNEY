# DAY 02 - HOW JAVA PROGRAM WORKS AND ITS 3 COMPONENTS

## 1. What is Java?

Java is a platform-independent and object-oriented programming language.

One of the major advantages of Java is:

**WORA - Write Once, Run Anywhere**

Java mainly consists of three important components:

1. JVM - Java Virtual Machine
2. JRE - Java Runtime Environment
3. JDK - Java Development Kit

---

## 2. JVM - Java Virtual Machine

JVM stands for **Java Virtual Machine**.

It is an abstract machine/software implementation that provides a runtime environment for executing Java bytecode.

The JVM does not physically exist as a hardware machine. It is implemented as software for different operating systems and platforms.

### How a Java Program Works

```
Java Program
     |
     ↓
  Compiler
     |
     ↓
  Bytecode
     |
     ↓
    JVM
     |
     ↓
 Machine Code
     |
     ↓
    CPU
     |
     ↓
   Output
```

When we compile a Java program, the Java compiler converts the Java source code into **bytecode**.

The bytecode can then be executed on different platforms using a compatible JVM.

This is the main reason Java provides platform independence.

### Java Execution Flow

```text
Java Source Code
       |
       ↓
    Compiler
       |
       ↓
    Bytecode
       |
       ↓
      JVM
       |
       ↓
 Machine Code
       |
       ↓
      CPU
       |
       ↓
    Output
```

---

## 3. JRE - Java Runtime Environment

JRE stands for **Java Runtime Environment**.

It provides the environment required to run Java applications.

A simplified representation of JRE is:

```text
JRE
 |
 ├── JVM
 |
 └── Java Libraries
```

Java libraries contain pre-written classes, interfaces, and methods that provide reusable functionality and help developers while writing Java programs.

---

## 4. JDK - Java Development Kit

JDK stands for **Java Development Kit**.

It provides the tools required to develop Java applications.

The JDK includes development tools such as:

- Java Compiler
- Debugger
- Other development utilities

It also provides the runtime components required to run Java applications.

A simplified representation is:

```text
JDK
 |
 ├── Development Tools
 │    ├── Compiler
 │    ├── Debugger
 │    └── Other Tools
 │
 └── JRE
      |
      ├── JVM
      └── Java Libraries
```

---

## 5. JVM vs JRE vs JDK

| Component | Purpose |
|-----------|---------|
| JVM | Executes Java bytecode |
| JRE | Provides the environment required to run Java applications |
| JDK | Provides tools required to develop Java applications |

---

## 6. Relationship Between JVM, JRE and JDK

The three components can be understood using the following simplified structure:

```text
JDK
 |
 └── JRE
      |
      └── JVM
```

### JVM

Responsible for executing Java bytecode.

### JRE

Provides the runtime environment required to execute Java applications.

### JDK

Provides the tools required to develop Java applications.

---

## 7. Why is Java Platform Independent?

Java follows the concept:

**Write Once, Run Anywhere (WORA)**

The Java source code is compiled into bytecode.

```text
Java Source Code
       |
       ↓
    Compiler
       |
       ↓
    Bytecode
```

The same bytecode can be executed on different operating systems using their respective JVM implementations.

For example:

```text
              Java Bytecode
                    |
        ┌───────────┼───────────┐
        ↓           ↓           ↓
      JVM         JVM         JVM
        ↓           ↓           ↓
    Windows       Linux       macOS
```

Therefore, the Java program does not need to be rewritten for every operating system.

## 9. Important Terms

### Source Code

The Java program written by the developer in a `.java` file.

### Bytecode

The intermediate code generated by the Java compiler and stored in a `.class` file.

### JVM

The component responsible for executing Java bytecode.

### JRE

The runtime environment required to run Java applications.

### JDK

The development kit containing tools required to develop Java applications.

### Compiler

The tool that compiles Java source code into bytecode.
